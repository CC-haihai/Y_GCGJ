## 0. 读之前：现状核对与三条设计原则

### 0.1 术语表

| 术语 | 含义 | 不要混用的说法 |
|---|---|---|

| 圆盘 | 右键长按 / 侧键触发的扇区菜单，切**当前图层** | — |

### 0.2 现状核对（源码为准，与需求描述的差异必须显式记录）

| # | 需求描述 | 源码事实 | 本文结论 |
|---|---|---|---|
| 1 | 图层切换面板底部有「取消 / 确定 / 完成」三按钮 | `LayerSelectionWindow.xaml` **没有任何底部按钮**，只有一个「同时设为当前图层」勾选框；应用靠 `Enter` / 双击 / 点行后关窗 | 两种形态都有问题。本文按"**两按钮**：取消 + 动态主按钮"收敛（§3.3）。"完成"一词严禁出现在本面板 |
| 2 | 图层列表有"勾选方块 + 多选" | 该面板的列表是 **ListBox 单选**，没有勾选框；"勾选 + 已选 N 个 + 取消/确定"来自**另一个弹窗**（`LayerPicker`，用于配置里选图层池） | "多选"在本面板的真实含义是 **CAD 里预选了多个图元**（`_selectedObjectIds`），不是多选图层。规范明确：**图层永远单选**（§3.4） |
| 3 | 鼠标划过行会预亮 | `LayerItem_MouseEnter/MouseLeave` 是**空方法**；图纸高亮只由"选中行"触发（`SelectionChanged → TriggerPreview`） | 预亮结论：**行内只做背景高亮，不联动图纸**（§3.7）。理由：hover 联动图纸会随鼠标扫动疯狂闪烁且开销大 |
| 4 | 标题栏有主题切换 ◐ | 确实存在（`ThemeToggle_Click`），且与主面板 / 胶囊条 / 圆盘的单一深色不联动 | 删除（§3.2）。插件是"深色单一主题" |
| 5 | 主面板"未保存"在左下角 | 确实在左下角、11px、`#F59E0B` 圆点 + 文字 | 位置保留（底部按钮左侧），**新增标题栏 3px 状态条四态**（绿/橙/灰/停用+未存盘双段，§4.2） |
| 6 | 启用开关"开关即时生效 vs 保存后生效"不清 | 开关立即写内存配置并标脏；但 `OnClosing` **无条件 `SaveNow()`**，所以 X / Esc / 完成**全都会落盘** | 明确规则："**状态类即时落盘，结构类延迟落盘**"（§4.3）。同时指出：主面板事实上没有"取消"路径，必须把这个模型讲明白，而不是假装有取消 |
| 7 | 两处都能"切配置文件/图层" | 胶囊条：点配置名 → 配置清单 → 切配置；**不能切图层**。圆盘：切图层（当前类别的图层池）；**不能切配置** | 不是重复，是"**同一件事的两个旋钮**"（改配置 vs 改图层）。重叠点在"用户以为都能改下一个动作去哪层"，需要文案与分工声明解决（§5.1） |
| 8 | 列表分「最近使用」「全部图层」两段 | 确实是同一个 ListBox 里的两个"标题项"，而且**标题项本身可被键盘选中/聚焦**；同名图层在"最近"和"全部"各出现一次 | 最近区降级为**快捷行**（不在列表里），标题行不可聚焦（§3.5）。这是 P1 可达性 + 认知负担问题 |
| **9** | 用户口述"CC 原来的分组是按图层前面的来排序的" | `LayerCategoryService.DetectCategories` 确实按 `ExtractPrefix`（`-` `_` `.` 前第一段，1–8 字取原文、否则前 3 字，统一大写）分组，**字母升序、`其他` 永远末位**；只有 ≥2 个图层的前缀才成组，零散前缀与图层 `0` 并入 `其他` | **前缀分组成立**。v2.0 曾把 CC 词条改成语义分类（建筑/结构/机电/其他），**已作废**——语义分类与图纸实际命名不对应（多数图里没有名叫"结构"的前缀），是假空态的另一个来源（§3.5、§9） |
| **10** | 主面板映射行"一个类别能配几个图层" | `PanelWindow.xaml.cs` `RefreshChips`：0 层 → 只有 `＋ 选图层`；1 层 → 只有 `＋ 再加一层`；≥2 层 → **摘要行 `N 层 · 当前层名` + 行尾 `＋`，点摘要行展开成 `WrapPanel` 换行 chips**；chip 点=设当前层、拖=排序（阈值 5px）、点色块/色号=改色、`×`=删这条映射 | **恢复 V1.0 图层池模型**。v2.0 的"chips 平铺 + 溢出折叠 `+N` 浮层"**整段作废**（§4.4、§9） |
| **11** | 展开态跨操作是否保持 | `_poolOpen` 是**窗口实例上的 `HashSet<string>`**，只在内存里；`BuildRows`（切配置 / 切图纸 / 重开都会走）**不清空它** | 规范定：会话内记忆、**不写盘**；**切配置 / 切图纸 / 关窗重开一律全部收起**（§4.4-E）。现状"切配置仍展开"是**与规范不符的偏差**，见 P2-9 |
| **12** | 前缀算法的退化行为是否可解释 | `ExtractPrefix`：切分后第一段长度 **1–8** 就用它，**>8 就取图层名前 3 个字符**（大写） | 会撞上"我的 `WALL_外墙` 为什么进了 `WAL`"。必须写进规范并向用户暴露（§3.5.2 边界表），不做静默行为 |

### 0.3 三条设计原则（针对"常年键盘、讨厌多余点击"的绘图员）

1. **键盘优先，鼠标不挡路**：任何操作都有键盘等价；默认焦点落在唯一需要打字的地方（搜索框）；不给高频动作加二次确认。
2. **一个值只在一个位置显示**：数量、状态、当前层，全局只有一处权威显示，其余地方只允许"不矛盾"的冗余（如胶囊条）。
3. **即时生效 + 可撤销，优于"先确认再生效"**：能撤销的就不弹框；只有"不可撤销且会丢数据"的动作才确认。

> **已决事项（2026-11-10，team-lead 拍板）**：本规范的三处方向性选择已定稿，不再作为待议项——**图层永远单选**（不做多选图层）、**不提供"关闭不保存"**（改动即时生效 + 关窗即写盘 + 「还原到打开时」补偿）、**只保留深色主题**（删浅色分支，将来要做浅色须另立项目）。完整条目与影响面见附录 B.3。

### 0.4 红线（违反即打回，不接受"看起来更好"作为理由）

| # | 红线 | 为什么是红线 |
|---|---|---|
| **R1** | **禁止降低控件边界的对比度**：可点矩形必须用 `LineControl`（40% 白，3.60:1）；**唯一允许的调整是把输入框底 `Raised` 换成 `Sunken`，不得回头调低边界透明度** | 这是把 1.4.11 从"未达标"修到达标的唯一手段。任何"为了观感把框调淡"的改动都会把已关闭的无障碍问题重新打开 |
| **R2** | 结构线（12%/20%）**不得**用于输入框 / 下拉 / 次按钮 / 勾选方块边界 | 结构线不是可点元素，用它画控件 = 回到不达标 |
| **R3** | 操作层（CC、圆盘、配置切换）**不得出现确认框**；结构层（删配置、保存失败仍关闭）必须确认 | 高频确认会把用户训练成"闭眼点确定"，反而摧毁确认框的效力 |
| **R4** | **不得新增窗口**：空状态、结果提示、错误一律内联或走命令行/胶囊条 | 用户在画图，多一个窗口就多一次打断与一次焦点争夺 |
| **R5** | 图层永远单选；一个值只在一处权威显示（3px 条管启停+存盘，状态点只管道启停，不得互相跟随） | R5 是 Q1 与"单一权威"的落地，破坏它会让用户无法判断当前状态 |
| **R6** | 主面板不存在"取消"：Esc / ✕ / 完成三者行为一致（保存并关闭），且**三层文案 + 可逆出口必须同时存在** | 只有规则没有出口 = 把风险转嫁给用户；只有出口没有规则 = 用户永远不知道改动什么时候生效 |
| **R7** | 列表**单击永不落地改动**；双击与主按钮才生效，且两者结果必须一致 | 单击即应用会让"浏览一下"变成"改坏图纸" |
| **R8** | 空状态**不出现图层名、不出现色块、不得有主按钮** | 证明"这里没有匹配项"时出现色块是自相矛盾；空状态里的主按钮会被当成"点它能解决" |

> 这 8 条是"后续任何优化都必须先过"的门槛。红线只在本文档维护，不由任何单方角色在别处改写（口径规则见 B.2-8）。

### 1.2 五个入口：一句话职责

| 入口 | 一句话职责 | 它**不该**做的事 |
|---|---|---|
| **主面板** | 改"规矩"：哪类图元归哪层、插件开不开 | 不在这里做单次换层（那是 CC / 圆盘） |
| **图层切换面板** | 做"这一次"：把手上这批图元挪到某层（或只切当前层） | 不在这里改映射规则、不切配置、不换主题 |
| **圆盘** | 手上正画着，不离开光标就换"下一条命令去哪层" | 不做批量改图元、不选配置、不弹二级菜单 |
| **胶囊条** | 告诉你"现在是什么状态"，并给一个换配置的入口 | 不做改映射、不做换当前层（避免遮挡绘图区抢点击） |
| **设置** | 改插件的行为（快捷键、别名、圆盘怎么触发） | 不放映射表、不放启停开关 |

> 一句话判据：**"改规矩"去主面板，"干这一票"去 CC，"手不离键"用圆盘，"我现在在哪"看胶囊条。**

### 1.3 三层职责模型（冲突时按这层判）

| 层 | 频率 | 承载 | 交互代价预算 |
|---|---|---|---|
| **结构层**（低频、重） | 首次 + 偶尔 | 配置的增删改、映射池、快捷键 | 允许多一步（弹窗、确认） |
| **操作层**（高频、轻） | 每条命令 | CC 应用、圆盘选层、配置切换 | **零确认**、单手可达、≤2 次点击 |
| **状态层**（常驻、静） | 一直 | 胶囊条、主面板 3px 条、状态点 | 只读；不加点击面 |

**判据**：任何"操作层"里的确认框都是缺陷；任何"结构层"里的静默不可撤销都是缺陷。

### 1.4 四条核心任务流程

**流程 A · 首次配置一条映射（结构层）**
```
QH ─▶ 主面板（标题栏黄色提示条"还没配置过图层，先填一行"）
   ─▶ 点某类别行的 [＋ 选图层] ─▶ 选择图层弹窗（勾 1~n 个）─▶ 确定
   ─▶ 该行**自动展开**：chips 带图纸颜色铺开，摘要行读到 `6 层 · E-04 造型线` ─▶ 底部出现「N 处未存盘」
   ─▶ [保存并关闭] ─▶ 底部闪"✓ 已保存"1.8s ─▶ 关窗 ─▶ 胶囊条刷新为"已启用 · 配置名 · 当前层"
```

## 3. 图层切换面板（CC）重做

### 3.1 六个语义问题的诊断（为什么现在会让用户判断错）

| 问题 | 机理 | 用户会怎么错 |
|---|---|---|
| **① 没有可见的主操作** | 单击行只"选中 + 预览"，真正的应用在 Enter / 双击里，界面上没有任何按钮暗示 | 点一层 → 觉得生效了 → 点 ✕ 关窗 → 其实什么都没做。回头看图纸还是老层，开始不信任插件 |
| **② "应用到谁"没有指示** | 同一面板有两种任务：有预选时搬图元、没预选时切当前层；两者的结果完全不同，界面上却长得一样 | 想切当前层却把一批图元挪走了；或反过来以为挪了其实只切了层 |
| **③ 「同时设为当前图层」勾选框恒在** | 无预选（当前层模式）时这个勾选框**完全无效**（代码里两个分支都会切当前层），但视觉上仍可勾 | 以为自己控制了某个行为，实际是空操作 |
| **④ 三段筛选同时存在** | chip + 搜索 + 「最近/全部」两段，最近区还会与全部区**重复同名项** | 用 chip 筛过 `E` 后忘了，搜不到就以为图层不存在 |
| **⑤ 「全部图层」标题行可聚焦** | 标题是 ListBox 里的项，↑↓ 会停在标题上 | 按了几次 ↓ 没反应/跳不动，以为卡了 |
| **⑥ 分类词条与图纸实际命名不对应**（v2.2 新增） | v2.0 把 chip 写成语义词条「建筑 / 结构 / 机电 / 其他」，但图纸里的图层是按前缀命名的（`A-墙`、`E-04 造型线`、`DIM-标注`），没有叫"结构"的东西 | 用户在「结构」下看不到 `E-04`，在「建筑」下看到一半；"我的结构层到底算哪个分类"变成每次都要猜的问题。**前缀是图里现成的、唯一的客观依据，语义分类是我们替用户猜的**——这也是 v2.2 把词条改回前缀的全部理由（§3.5.1） |

| C. **取消 + 动态主按钮**（本文采用） | 主操作唯一且自解释；文案即结果预览 | 需要维护两套文案 | ✅ 采用 |

|---|---|---|---|---|

### 3.4 应用对象语义澄清（本次最重要的一条）

**核心决定：图层单选，不做多图层勾选。**（Q1，2026-11-10 team-lead 已拍板，不再作为待议项）

| 方案 | 说明 | 判定 |
|---|---|---|
| A. 列表勾选多个图层 → 图元分摊到多层 | 需要"哪个图元去哪层"的二次分配，面板装不下 | ❌ 否决（这是"图层分配器"另一个产品） |
| B. **图层单选 + 图元集合一次移动**（本文采用） | 一批图元 → 一个目标层，符合 95% 真实动作 | ✅ 采用 |

**模式条是唯一权威指示**，两种模式互斥且视觉可分辨：

| 模式 | 判定条件 | 模式条文案 | 底部勾选框 | 主按钮 |
|---|---|---|---|---|
| **对象模式** | 打开面板时 CAD 有预选（含"选择图元"提示里选到的） | `将 3 个图元移到目标层` + 右侧「改选 ▸」 | 显示、可用 | 「移到该层」 |
| **当前层模式** | 打开时没有预选，用户直接回车 | `仅切换当前图层（未选中任何图元）` | **隐藏**（不留无效控件） | 「设为当前层」 |
| 图元被清空 | 对象模式下对象全被删除/取消选择 | `图元已失效，将只切换当前图层` + 允许「改选 ▸」 | 隐藏 | 「设为当前层」 |

**「改选 ▸」的行为**：关闭面板 → 回到 CAD 的选择提示（保留已应用的记忆）→ 重新选完后再弹回面板。允许中途 Esc 放弃，此时不产生任何改动。

**「改选 ▸」的交互规格**（已与视觉对齐，`01-visual-spec.md` §11）

| 项 | 规格 |
|---|---|
| 视觉 | 11.5 DIP 文字按钮，无常态底色，**hover 只换字色（`AccentLine` → `Text`），不加底色**——加了底色它就长得像主按钮，而底部已经有一个主按钮了 |
| 可点区 | **满条高 26 DIP**（不是文字本身的高度），右侧内边距 8 → 实际水平可点 ≥ 44×26 |
| Tab | **进 Tab 序列**（模式条本体是读数面板、不可点、不占停靠点，只有它能聚焦） |
| 键盘 | `Alt+R`（改选 = Reselect）；`Enter` 语义仍是"应用"，不因焦点在此而改变 |
| 状态 | 仅对象模式与"图元已失效"两态出现；当前层模式不存在该按钮（整条 `Collapsed` 后不留空白高度） |
| 读屏名 | `改选图元（当前 3 个）` |

**结果预览要求**：主按钮文案 + 模式条必须让用户在**按下之前**就知道三件事：几个图元、去哪个层、要不要顺带改当前层。三者缺一即视为未完成（验收 §8-3）。

### 3.5 筛选路径收敛（chip / 搜索 / 最近 的优先级与层级）

#### 3.5.1 前缀组词条的生成规则（唯一算法，禁止另写一套）

> v2.2 恢复。词条**不是**产品内置的语义分类，而是**从这张图纸的图层名里算出来的**。源码依据：`LayerCategoryService.DetectCategories` / `ExtractPrefix`。任何"再补一个固定的分类表"的做法都算违规（§9）。

| # | 规则 | 示例（输入 → 前缀） |
|---|---|---|
| 1 | 取图层名在 **`-` `_` `.`** 三个分隔符处切开的**第一段**，并 trim 首尾空格 | `A-墙` → `A`；`WALL_外` → `WALL`；`DIM.标注` → `DIM` |
| 2 | 该段长度 **1–8** → 整段就是前缀 | `E-04 造型线` → `E`；`DIM-标注` → `DIM`；`墙-外` → `墙` |
| 3 | 该段长度 **> 8** → **退化为图层名的前 3 个字符**（见 §3.5.2 的风险条与 tooltip 要求） | `ELEVATION-外墙` → `ELE` |
| 4 | 统一**转大写**，大小写不同视为同一组 | `a-墙` + `A-柱` → 同组 `A` |
| 5 | **只有 ≥2 个图层的前缀**才成为一个独立 chip；**只出现 1 次的前缀并入 `其他`** | `T-文字` 只有 1 层 → 不进 `T` 组，计入 `其他` |
| 6 | 图层 **`0`** 不属于任何前缀组，其计数并入 `其他` | `0` → 计入 `其他` |
| 7 | 顺序：**`全部` 首位 → 各前缀组按字母升序（A→Z，中文按码位）→ `其他` 永远末位**。`全部` 与 `其他` 的位置**不可配置、不可拖拽** | — |
| 8 | 词条文本 = **前缀原文（大写、不翻译）**，后面跟一个 8.5 DIP 淡色计数；tooltip 写 `N 个图层` | `A` + `6`，tooltip `6 个图层` |
| 9 | 词条总数 = `全部` + 前缀组数 + `其他` | 见下表样例 |

**样例验证（team-lead 给定，作为验收基准 §8-28）**

图纸图层共 14 个：`A-墙`、`A-柱`、`A-门窗`、`A-楼梯`、`A-楼板`、`A-散水`、`E-04 造型线`、`E-05 辅助线`、`H-填充`、`T-文字`、`DIM-标注`、`F-家具`、`X-设备`、`0`

| 词条 | 计数 | 来源 |
|---|---|---|
| `全部` | 14 | 图纸图层总数（含 `0`） |
| `A` | 6 | `A-` 出现 6 次，≥2 → 成组 |
| `E` | 2 | `E-` 出现 2 次，≥2 → 成组 |
| `其他` | 6 | `H`(1) + `T`(1) + `DIM`(1) + `F`(1) + `X`(1) + `0`(1) = 6，末位 |

> **必须接受的现实**：这张"画得很规矩"的图最终**只有 2 个前缀组 + 其他**。所以在做评审与验收时，**不得**用"词条不够丰富""看起来没分类"作为缺陷；也不得为了"让分类看起来更漂亮"去加语义分类、去把 1 层的前缀也提成组。`全部` 的计数与各词条计数**不是相加关系**（`全部` 是总数），UI 上不得出现"14 = 6 + 2 + 6"这类暗示。

#### 3.5.2 边界情况（全部必须实现，逐条可验收）

| 情况 | 输入 | 结果 | 规定与风险提示 |
|---|---|---|---|
| **图纸只有 `0` 层** | `0` | 词条只有 `全部 1` + `其他 1`，**没有任何字母 chip** | 两个词条筛选结果相同，属**已知冗余，但 chip 行照常显示**（team-lead 2026-11-10 拍板：按 V1.0 行为，不为它加空态、不隐藏）。**不得**因此假装成"没图层"走空状态——列表里那一行 `0` 必须照常出现 |
| **全部图层都是零散前缀** | 10 个前缀各 1 层 | 只有 `全部 10` + `其他 10` | 与上一行同构，同样照常显示。此时筛选的唯一有效手段是**搜索**；不因为"看起来没分类"而隐藏 chip 行 |
| **前缀 > 8 字符（退化）** | `ELEVATION-外墙`、`ELEVATION-内墙` | 组名 `ELE`（不是 `ELEVATION`） | **必须在 tooltip 里说清来源**：`2 个图层 · 前缀「ELEVATION」超过 8 字，取前 3 字`。否则用户会问"我的图里没有 ELE 这个东西"。这是本算法**唯一需要向用户解释**的行为，不得静默 |
| **没有分隔符** | `A墙`、`A柱` | 整段 `A墙` / `A柱` 各成组（**不会**并进 `A` 组） | `A-墙` 与 `A墙` 是两组。这是算法的客观行为，不做"智能合并"（合并就变成语义猜测了） |
| **中文前缀** | `墙-外`、`墙-内` | 组名 `墙`（1 字，1–8 内取原文） | 中文前缀完全可用，词条照原样显示，不翻译不转码 |
| **以分隔符开头** | `-墙`（罕见） | 退化取整名（大写） | 不做特殊处理，也不报错 |
| **同一前缀但大小写混用** | `a-墙`、`A-柱` | 合并为 `A` | 视觉上词条恒为大写，与图纸里的写法可能不一致——这是有意的（保证合并可预期） |

#### 3.5.3 出现条件与溢出行（含禁止项）

**出现条件**

| 条件 | chip 行 |
|---|---|
| 图纸无图层（LayerTable 空） | 不显示，走 §3.9「图纸无图层」空状态（**唯一**不显示的情况） |
| **只有 1 个图层** | **照常显示**（team-lead 2026-11-10 拍板，按 V1.0 行为）。`全部` 永远显示；`其他` 计数为 0 时省略 → 极端情况整行只剩 `全部 1`，**这是对的，不加空态、不隐藏** |
| ≥2 个图层 | 显示：`全部`（首位）+ 各前缀组 + `其他`（末位） |

**更易条件（源码口径，两条都要满足）**：`全部` 恒显示（等同 `!IsOther`）；`其他` **仅当 `Count > 0`** 才显示（源码即 `!IsOther || Count > 0`）。所以"词条数 ≥1"永远成立，chip 行只有"图纸完全没有图层"这一种不显示的理由。

**溢出：最多 2 行，超出折叠成末尾一个 `+N`（team-lead 2026-11-10 拍板，替代 v2.2 早先的"纵向滚动"）**

| 项 | 规定 |
|---|---|
| 排布 | chip 组**允许换行**（`WrapPanel`），行间距 6 |
| 行数上限 | **2 行**（22 + 6 + 22 = 50 DIP）；≤2 行时既无滚动条、也不出现 `+N` |
| 超过 2 行 | 第 2 行末尾放一个与 chip 同尺寸的 **`+N`**（`N` = 被折叠的词条数，10.5 `TextDim`），放得下的词条照常铺开。**折叠从字母序末位开始**——因为 `其他` 永远排最后，所以它会**优先被折进去**（已知取舍：`其他` 的入口变成"点 `+N`"或走搜索，不为了它破坏字母序） |
| 不做纵向滚动 | **chip 区自身永不滚动**。理由：chip 条只有 22 高，一旦自带纵向滚轮，用户想滚图层列表却滚到了分类条——违反「滚轮语义不得错乱」。同一纪律的三处出处并列：**`01-visual-spec.md` §6.13「滚动条」**（跨文件，视觉侧原始条款）、本文件 §3.7 鼠标流的滚轮行、§9-X2 ② |
| `+N` 点开 | **纵向清单浮层**（复用原浮层规格）：项高 28、系统滚动条（**不自定义模板**）、`Esc` / 点外部关闭、**不改变 chip 区高度、不改变窗口高度**（覆盖层） |
| 选中 | 点某项 / `Enter` → **浮层收起，该前缀组成为当前筛选**，列表即时过滤；`+N` chip 进入**选中态**并用 tooltip / 读屏给出 `当前筛选：E（另有 2 个已折叠分类）`。**不重排 chip 顺序**（当前筛选靠 `+N` 的选中态承载，不靠把它提到前排） |
| 键盘 | `+N` 在**本组那 1 个 Tab 停靠点内**（`←/→` 能走到）；`Enter`/`Space` 打开浮层；`↑↓` 移动（不循环）、`Enter` 选中、`Esc` 关闭并**焦点回 `+N`** |
| 为什么这次允许 `+N` | 与映射行那次被否决的 `+N` **不是一回事**：映射行折叠时藏的是"**有几层**"和"**当前是哪层**"两个关键读数，CC 折叠藏的只是"**还有哪些分类**"（当前筛选仍在 `+N` 的选中态上可见），且点开即见、不改变行高 |
| 禁止 | ❌ chip 区纵向/横向滚动 ❌ chip 文字截断 ❌ 把 chip 区做成下拉 ❌ `+N` 里放"设置/管理"等非筛选动作 |
| 词条来源 | **必须由 §3.5.1 算法算出**；禁止写死词条表、禁止人工排序、禁止让用户自定义分组 |

**关键规则（按此消灭冗余路径）**

1. **打字即重置 chip**：搜索框一有输入，chip 视觉回"全部"。理由：绘图员按名字搜的时候不记得自己筛过什么，"搜不到"的假空态是最伤的错。
2. **最近区不重复进列表**：改后快捷行是**独立控件**，不与"全部图层"列表重复。键盘 ↑↓ 只在列表里走，绝不会在两条同名项之间来回。
3. **不显示无意义的 chip**：`其他` 计数为 0 时不显示该 chip；**但 chip 行本身只要是"图纸里有图层"就显示**（哪怕只剩 `全部 1`，见 §3.5.3）。
4. **chip 上是"词条 + 计数"**：`A 6`。搜索态下显示为「命中数/总数」（`A 2/6`），用于判断该不该换 chip。
5. **默认 chip = `全部`** + 搜索空 + 最近行可见 → 用户第一眼看到"最近用的 + 字母序全部"，符合复用心智。
6. **chip 组只占 1 个 Tab 停靠点**（roving focus），与 §3.6 / A.2 一致；换行不增加停靠点。

### 3.7 鼠标流

| 手势 | 行为 | 理由 |
|---|---|---|
| 单击行任意位置（含色点、状态图标） | 设为当前项 + 图纸预览高亮该层图元 | 小目标不设死区；预览是"确认是不是这层"的关键 |
| 双击行 | 应用并关窗（= 主按钮） | 高频用户的最快路径，同时是唯一"双击有副作用"的地方 |
| 鼠标划过行 | **只做行背景高亮**，不联动图纸 | 见 §0.2-3；hover 联动会造成闪烁与开销 |
| 划过"最近"快捷项 | 行内高亮 + 提示"双击应用" | 与列表统一：单击不产生副作用 |

### 3.9 空状态（四类，全部要有文案与出路）

**出路按钮文案已定稿**（视觉侧只给结构，字面值以本表为准；全部为 32 高次按钮，禁止出现主按钮）

| 场景 | 判定 | 文案（第一行 / 第二行） | 出路按钮（字面值，逐个） | 点击后的焦点 |
|---|---|---|---|---|
| **无匹配（chip = 全部）** | 过滤后 0 行且筛选词条为 `全部` | `没有匹配「e07」的图层` / `改个关键词，或检查拼写` | `清除搜索` | 回搜索框并全选残留文字 |
| **无匹配（chip ≠ 全部）** | 过滤后 0 行且前缀组生效 | `没有匹配「e07」的图层` / `当前只显示「E」分组` | `清除搜索` + `显示全部分组` | 前者回搜索框；后者回搜索框但保留关键词 |
| **前缀组为空** | 该 chip 下 0 行（无关键词） | `「E」分组下没有图层` / `这个前缀的图层可能都在别的分组里` | `显示全部` | 回列表首行（若无行则回搜索框） |
| **图纸无图层** | LayerTable 为空（极少） | `当前图纸没有图层，无法切换` / — | `关闭`（列表与主按钮同时禁用） | 焦点落 `关闭` |
| **全部被锁/冻结** | 有行但都不可绘 | 不禁用；行内状态列显示"已锁定/已冻结" | —（不属空状态） | — |

**空状态的七个硬约束**

1. 文案里**必须出现当前生效的过滤条件**（关键词用「」包起来、分组名用「」包起来），让用户能推断为什么空。
2. 出路按钮必须是**真出路**：点完一定让列表里有内容或让窗口关闭，禁止出现点了没反应的按钮。
3. 空状态**不吃键盘**：`↓`/`Enter` 在空状态下不产生动作也不报错；`Esc`、`Ctrl+F` 照常可用。
4. 空状态**不替换搜索框与 chip**（它们必须还在原位可操作），只替换列表区。
5. **空状态一律内联，绝不新增窗口**（2026-11-10 确认）：四类场景全部在列表区内表达，出路用文字按钮。任何"弹个框告诉用户没有图层"的做法都是把可恢复的空结果升级成打断（底线，不得破）。
6. **空状态里不出现图层名、不出现色块**：它的职责是证明"这里没有匹配项"，再放一个色块或半截图层名是自相矛盾。只允许一个中性图标 + 两行文字 + 出路按钮。
7. **出路按钮的排布判定**：**并排为默认**；仅当两个按钮的自然宽度之和 **> 可用宽度**时才竖排（竖排时等宽、右对齐、间距 8）。**不用"窗口小于某宽度"作判据**——按后者，用户把窗口调窄就会莫名变成单个竖排，很突兀。实测 320 宽（可用 284）时最长组合「清除搜索」+「显示全部分组」约 192，**并排放得下**。

**空状态文案禁令**：不写"暂无数据"（无信息）、不写"请重试"（用户没法重试）、不写"联系管理员"。

### 4.1 配置区：**保持 4 个并列图标**（v2.1 推翻 v2.0 的「收敛成 ⋯ 菜单」）

> **裁决记录（用户原话，2026-11-10）**：**「这个配置加图层不对啊，原来那样挺好的你改他干嘛，现在我都不太理解怎么调整或者增加图层了」**。
> v2.0 曾把这一排收成「＋新建 / ⋯更多」以减少误点删除，**已作废**。理由：这四个动作是"改配置"的全部入口，一天里用得着的频率远高于"怕误删"的频率；把重命名/复制藏进「⋯」之后，用户找不到"复制一个配置改改看"这种最常见的用法，反而更容易一怒之下直接改当前配置。

**定稿（线框）**

```
配置  [ 我的图层配置              ▾ ]   ＋  ✎  ⧉  │  🗑
```

| 控点 | 内容 | 说明 |
|---|---|---|
| 下拉 | 切换配置 | 立即生效、立即落盘（§4.3） |
| `＋` | 新建配置（沿用当前配置的图层设置） | 与原版文案一致，不叫"另存为" |
| `✎` | 重命名当前配置 | |
| `⧉` | 复制当前配置，改出一个新的 | |
| `🗑` | 删除当前配置（至少保留一个） | `IconDanger`：常显 `Danger` 色，与前三者之间加 1px 分隔线 |

**误点删除改用"颜色 + 分隔"解决，不用"收起来"解决**（三重保护，全部保留）：
1. **颜色保护**：唯一常显 `Danger` 色的图标，前三个是 `TextDim`。余光里就能分出"最右那个是删"。
2. **位置保护**：删除与复制之间一条 1px `LineStrong` 分隔线，宽度 14，上下居中。
3. **能力 + 文案保护**：确认框标题写配置名，正文写明「这个配置里的 12 项映射会一起删除，无法撤销」；仅剩 1 个配置时该项禁用。

> **被否决的方案留档**：`⋯` 菜单收纳。否决理由不是"误点"，而是**发现性**——菜单项带文字确实更清楚，但前提是用户愿意先点开菜单。改映射是结构性低频操作，人们的行为是"看一眼就知道能做什么"，不是"先探索菜单"。

### 4.1.1 加图层：入口必须常驻可见（v2.1 新增）

> **同一个用户反馈的第二半**：「现在我都不太理解怎么调整或者增加图层了」。v2.0 把行内 `＋` 做成 **hover 才出现**（`opacity 0 → 1`），视觉稿上 7 行里 1 行有加号、其余 6 行空白——用户当场读不出来"这里能加层"。

**定稿**

| 行状态 | 入口 | 说明 |
|---|---|---|
| 已有 **≥2** 个图层 | 摘要行末 `＋`（22×22，**常驻**） | 点开选择图层弹窗（多选），追加到该类别 |
| 已有 **1** 个图层 | `＋ 再加一层`（文字按钮，**常驻**） | 1 层时没有摘要行，这个按钮就是入口 |
| 图层池为 **0** | `＋ 选图层`（文字按钮，**常驻**） | 空行是"首次配置"必经之路，必须给一句人话 |
| 达到 16 个图层上限 | `＋` 置 `disabled`（不隐藏） | tooltip「一类最多 16 个图层（圆盘扇区上限）」，见 §4.4.5 |

**三条禁止**
1. ❌ 不得用 hover / 焦点才显示入口（`Visibility` 或 `Opacity` 切换都算）。
2. ❌ 不得把"加层"做成只能从下拉框里手打图层名（打错一个字母就配了个不存在的层，这正是选择图层弹窗存在的理由）。
3. ❌ 不得把 `＋` 放进行尾状态列（状态列只读，见 §5.5）。

**"调整"的四个动作，各自有可见依据**（前提：**先点摘要行展开**；收起态只做"读数"，不做"编辑"）

| 用户想做的事 | 操作 | 视觉依据 |
|---|---|---|
| 看"这一类有几层 / 现在用哪层" | 不用操作，收起态摘要行直接读到 `6 层 · E-04 造型线` | 这是摘要行存在的理由（v2.0 的 `+N` 折叠恰恰把这两件事都藏了） |
| 换"下一条命令去哪层" | 展开后点某个 chip | 当前层 chip 用 `AccentSoft` 底 + `LineControl` 内描边 + 名称 `#FFFFFF`，点完高亮立刻跳过去 |
| 改这一层的颜色 | 展开后点 chip 里的色块**或色号文字** | 色块 9×9 带 `SwatchLine`，色号同为可点区（色块太小），tooltip 写明"点一下改色（只改这一层）" |
| 删掉这一层 | 展开后点 chip 里的 `×` | `×` 的 hover 变 `Danger`；只删这一条映射，不删图纸里的图层 |
| 调顺序（圆盘扇区序） | 展开后 chip 左右拖（或 `Ctrl+←→`） | 拖动时 chip 半透明并按实时位置重排；位移 <5 DIP 视为点击 |

### 4.2 未存盘态强化

**现状**：左下角 11px 橙点 + "未保存"，与右下"完成"按钮之间隔了一大片空白，且用词"未保存"暗示"不点完成就白改"（实际关窗也会存，语义反了）。

**方案：三处协同，一静一动**

| 位置 | 形态 | 语义 |
|---|---|---|
| 标题栏最左 3px 竖条（高 48 分两段） | 绿 `#34D399` = 已启用且无未存盘；橙 `#F59E0B` = 有未存盘；灰 `#8A93A0` = 已停用且无未存盘；**停用 + 有未存盘 = 上橙 26 / 下灰 22 双段** | 余光可见，不占文字位。双段而非纯橙：纯橙会丢掉"现在是开还是关"，而"关着还改了映射"恰恰是最该让人愣一下的组合 |
| 底部左侧 | `● 3 处未存盘`（带数量）；保存后变 `✓ 已保存` 1.8s 再淡出 | 数量化，可判断"值不值得现在存" |
| 右下按钮 | 文案固定「保存并关闭」；有未存盘时按钮右侧加一枚 6px 橙点 | 把"要存"和"怎么存"放在同一视觉组 |

**与胶囊条状态点的分工（避免两处色语互相污染）**：3px 条 = 启停 + 存盘（4 态）；7px 点 = **只表示启停**（绿/灰）。点做校验、条做汇总，三态下颜色完全一致，只有"停用 + 未存盘"这一格是条多一段。**禁止**让状态点跟随存盘状态（否则同一时刻两处不同色，等于没有权威）。

**用词修正**：`未保存` → **`未存盘`**。理由：改动已经生效（下一条命令就按新映射归层），只是没写进配置文件。"未保存"会让用户以为改动还没生效。
> 口径：视觉侧已全量替换（`01-visual-spec.md` v1.1）。本规范自本节起统一用「未存盘」；全文其余出现的「未保存」**仅作为旧文案引用**（在 §0.2、§4.2 现状描述与 §7 现象列里），不属新文案。§6.2 文案表已无旧词。

**关闭时的兜底**：关窗（X / Esc / 按钮）一律尝试落盘；写盘失败 → **不关窗** + 底部横幅给出文件路径与原因 + 一个明确的 `仍然关闭（改动会丢失）`。现状已基本如此，保留并把文案统一到 §6.2 的表里。

### 4.3 启用开关与保存的关系（把规则写成一句话）

**规则（唯一版本，界面上必须能读到这句）**：
> **开关和配置切换立刻生效也立刻写盘；映射的修改立刻生效，但要「保存并关闭」才写盘。**

| 项 | 生效时机 | 落盘时机 | 为什么 |
|---|---|---|---|
| **启用开关** | 立即（钩子读内存） | **立即**（改为显式写盘，现状是延迟到关窗） | 全局状态、跨图纸跨会话；用户绝不预期"上次关了没存" |
| 配置文件切换 | 立即 | 立即（现状已如此） | 同上 |
| 快捷键 / 别名 / 圆盘触发 | 立即 | 随面板保存 | 改完就该能用；但属于结构层，允许批量后一起存 |
| **类别 → 图层映射** | 立即（下一条命令按新映射） | 点「保存并关闭」/ `Ctrl+S` | 一次会话会连改十几行；每行都写盘会让 ini 反复落盘、且用户失去"整体确认"的机会 |

**开关的反馈设计**（解决"开关到底做了没"）：
1. 拨动瞬间：标题栏状态点/竖条、`已启用`↔`已停用` 文字、提示行文案、胶囊条，**四处同时变**（现状已 3 处，加胶囊条）。
2. 若此刻 CAD 正在一条命令中间：提示行追加 `下一条命令生效`（与圆盘口径一致）。
3. 关闭时若仍有未存盘映射改动：先在底部闪一次 `开关状态已保存；映射改动也已保存`（因为关窗会落盘，别让用户以为要再点按钮）。

**现状缺陷明确记录**：面板事实上**没有"取消"**——`OnClosing` 无条件保存。

**已定稿（Q2，2026-11-10）**：不引入"关闭不保存"，改为把模型讲明 + 给补偿出口。三层文案缺一不可：

| 位置 | 文案 | 时机 |
|---|---|---|
| Esc / ✕ 的 tooltip | `关闭并保存（改动已生效）` | 常驻 |
| 提示行（脏态） | 变体 A：`改动已生效，未写入配置文件` ／ 变体 B：`改动已生效，未写入配置文件（保存后写入）` | 有未存盘改动时常驻；**A/B 由「还原」是否存在决定，见下** |
| 关闭后一次性闪 | `改动已保存` | 首次关窗后一次，之后不再出现（记持久化标记） |
| 脏态时的补偿出口 | 变体 A：提示行右侧文字按钮 `还原到打开时`（**已定案进 V1.0，优先级 P2**）；变体 B：**无此按钮、也不留空位** | 有未存盘改动时出现；点了回到进入面板时快照，**不关窗** |

**A/B 变体必须同批切换（禁止混用）**

| 变体 | 触发条件 | 提示行 | 右侧按钮 | 禁止 |
|---|---|---|---|---|
| **A（主方案）** | V1.0 含「还原到打开时」 | `改动已生效，未写入配置文件` | `还原到打开时` | — |
| **B（降级：还原被砍）** | 排期不足、发布版不含该功能 | `改动已生效，未写入配置文件（保存后写入）` | **无按钮、不占位** | ❌ 提示行不得出现"还原"字样；❌ 不得留一个不可点的空位或禁用态按钮；❌ 不得只在发布说明里说、界面上还暗示有退路 |

> **为什么 B 必须换文案**：一边说"改动已生效、未写入配置文件"，一边没有任何退路，用户的自然反应是去找那个"能撤销的按钮"——找不到就会以为是自己没发现。文案必须当场把出路指向唯一真实存在的动作（保存），而不是留一个想象中的出口。

> **「还原到打开时」的排期规则（2026-11-10 定案）**：本功能**属于 V1.0 范围**，不是可选项——Q2 的整套逻辑建立在"永远有一个可逆出口"上，砍掉它就变成"关窗即存 + 无退路"，用户第一次误操作后不会再信任这个模型。
> **若实现排期实在不足，三件事必须同批完成**：① 发布说明写明"本次不提供还原"，**放在更新日志顶部**，不得埋在段落中间；② 提示行文案切到**变体 B**（见上表）；③ 界面不得残留任何"还原"暗示（字样、空位、禁用按钮都不行）。**漏掉 ② 或 ③，就等于给用户指了一个不存在的按钮。**

> 原则：这个模型的代价是"用户没有后悔药"，所以两件事必须做到——**每次关窗都真的写盘了**（写不进去就不关窗，见 §6.4），以及**永远有一个可逆出口**（「还原到打开时」）。只讲规则不给出口，等于把风险转嫁给用户。

> **排版已核对**：脏态提示行「改动已生效，未写入配置文件」13 字 × 11.5 ≈ 150 DIP；主面板 470 扣左右 36 后可用 434、右侧主按钮约 104，中间余量约 180 DIP —— **放得下，不需要为这段文字缩字号或删字**。125% 缩放下 DIP 数值不变（缩放只影响物理像素），不会因缩放挤爆。

### 4.4 映射行：图层池的「摘要 → 展开」模型（v2.1 恢复 V1.0，v2.2 补三态 / 键盘 / 上限）

> **裁决记录（用户原话）**：「**我原来有些设计是考虑到大于 4 个图层的单个元素，你现在这个完全不如原来的**」。
> v2.0 把映射行做成「chips 平铺 + 溢出折叠 `+N` 浮层」，**整段作废**（否决理由见 §9）。它把两件事同时藏了起来：**"这个类别有几层"** 和 **"现在用的是哪层"**。一个类别配 6 层时，行内只剩 3 个 chip + 一个 `+3`，用户既数不出总数，也看不出当前层——而这两件事恰好是他打开主面板最想确认的。
> 恢复后的模型是 V1.0 的**摘要-展开**：收起时一行读数把这两个信息说全，需要动手时才铺开成 chips。

**编辑动作的落点（这一张表不变，只是"行内"现在指"展开后的 chip 内"）**

| 编辑动作 | 位置 | 判定理由 |
|---|---|---|
| 选目标图层（1~16 个） | **弹窗**（选择图层弹窗，勾选多选） | 图层名背不下来，必须从图纸列表里勾；多选需要勾选框；还支持"图纸里没有的层"显式列出 |
| 删除某个图层 chip | **行内**（展开后 chip 右侧 `×`） | 高频微操，弹窗代价太高 |
| 调整图层池优先级 | **行内**（chip 左右拖 / `Ctrl+←→`） | 圆盘只取前 16 个，顺序有实际意义 |
| 设"下一条命令用哪层" | **行内**（点 chip） | 这是本模型最重要的一个动作，必须能在一行里完成 |
| 类别增删 | **不提供** | 类别是插件的语义骨架，增减类别是产品决策不是用户配置 |
| 手打图层名 | **不提供**（现状可行） | 打错一个字母就配了个不存在的层——这是选择图层弹窗存在的全部理由 |

#### 4.4.1 三态与摘要文案（定稿）

| 池内层数 | 行内形态 | 摘要副文案 | 行尾 | 状态列 |
|---|---|---|---|---|
| **0 层** | 池区只有 `＋ 选图层` 文字按钮（常驻；下拉为空，无摘要行、无虚线占位 chip） | — | 按钮自带 `＋` | `待配置` |
| **1 层** | 池区只有 `＋ 再加一层` 文字按钮；**层名由该行的可编辑下拉显示** | — | — | `正常` / `缺失` / `已冻结` |
| **≥2 层（收起）** | 摘要行 `▸ 6 层 · E-04 造型线` | `N 层`（10.5 `TextDim`）+ `·` + **当前层名**（10.5 `AccentLine`，`MaxWidth 190`，超长**尾部省略**，tooltip 全名） | 独立 `＋`（22×22） | 同上 |
| **≥2 层（展开）** | 箭头变 `▾`，摘要下方铺开 chips（`WrapPanel`，换行） | 同上（读数不因展开而消失） | 独立 `＋` | 同上 |

**摘要行的可点区域与文案**

| 项 | 规定 |
|---|---|
| 可点区 | **整条摘要都是同一个可点矩形**：箭头 + `N 层` + `·` + 层名，一律可点；高度 = 该行内容高（≥26 DIP），不是文字自身高度 |
| `＋` 不属于摘要 | `＋` 是**独立控件**，点它永远开选择图层弹窗，**不会**触发展开/收起。两个可点区之间留 5 DIP 间距 |
| hover | 摘要矩形描 1px `LineStrong`（不给底色）；`＋` 按次按钮规则 |
| tooltip（收起） | `展开图层池（换层 / 改色 / 删层都在这儿）` |
| tooltip（展开） | `收起图层池` |
| 1 层时为什么没有摘要 | 层名已经显示在同一行的可编辑下拉里，再来一条 `1 层 · E-04` 是同一值的第二处显示（违反 §0.3-2"一个值只在一个位置权威显示"） |

> **可编辑下拉仍然存在（V1.0 现状保留）**：每行第 1 行仍是那个显示 `A-墙 ; A-柱 ; …` 的可编辑下拉，摘要行在它下面。它同时承担"1 层时的层名显示"和"手工救急"（配置文件被外部改坏时能直接看出池里到底有什么）。
> **但它不是推荐路径，也不作为宣传口径**：摘要是主读数，chips 是主动作，下拉是兼容保留；三者的分工写在这里，避免"三个地方都能改同一个池"变成三个都改不明白。

#### 4.4.2 展开后的行高与对表格的影响（判定 + 结论）

| 影响面 | 判定 | 理由 |
|---|---|---|
| 行高 | 收起 ≈ **48**（下拉行 26 + 3 间距 + 摘要 ≈18）；展开 = 收起 + 4 + chips（`k` 行 × 22 + (k−1) × 6）→ 单行 chips ≈ **78**，三行 ≈ **126**。**行高随内容增高，不设上限** | chips 必须换行（禁折叠、禁横向滚动），行高就必然可变；把行高钉死在某一固定值会截断 chips，等于回到"藏信息"。8 行全是收起态时 ≈384 DIP，主面板 MaxHeight 740 仍可一次看全 |
| 下方行 | **允许被推挤，禁止覆盖浮层** | ① 覆盖层会盖住下方行的摘要与状态列，而用户展开一行时往往正在纵向对照"8 个类别各配了几层"；② 展开是一次性、方向单一（向下）的动作，位移可预期；③ 覆盖层要处理边界避让 + 点外关闭 + 焦点陷阱，成本高且易出 bug |
| 滚动位置 | **不主动改变滚动偏移**；只补一条最小补偿：若展开使摘要行顶边跑出视口（它是视口内最后一行），则**滚动最少距离**让其顶边贴齐视口顶部；**不滚到 chips 末尾** | 展开后用户要看的就是 chips，不能让它们长在视口外；但也不能把整张表甩走 |
| 状态列 | **展开时状态列不参与整行垂直居中**，仍与"类别 + 摘要第一行"同基线 | 否则展开 3 行 chips 后 `正常` 两个字飘到行中线，与相邻行错位，看起来像另一列 |
| 列宽 | **不改变任何列宽**（类别 76 / 池弹性 / 状态 `Auto` ≤72） | 列宽跳动会让 8 行表格整体错位，代价远高于收益 |
| 多行同时展开 | **允许**（不是手风琴） | 用户要对照两类的池子时，强制互斥展开会逼他来回点两次 |
| 动效 | ≤120ms，只做透明度/高度插值，不做位移弹跳 | 高频结构层操作，动画只服务"知道发生了什么" |

> **一句话结论**：**允许推挤、不遮不挡、状态列不动、滚动只做最小补偿。**

#### 4.4.3 展开态的保持规则（只在本次会话内记忆）

| 操作 | 展开态 |
|---|---|
| 本次会话内展开 / 收起 | **记住**（内存集合），**不写 ini、不进配置、不同步任何文件** |
| 切配置 | **全部收起**（不同配置的池子内容不同，带着别人的展开态过去只会误导） |
| 切图纸（CAD 打开/关闭/切换图纸） | **全部收起**（图层可能已不存在，保持展开会露出"缺失"层） |
| 关窗重开 | 全部收起（会话结束） |
| 从选择图层弹窗新增/追加后 | 若该行池 ≥2 层 → **自动展开该行**，焦点落摘要行（刚勾完多半要挑当前层或改色，收着就白费一次点击） |
| 删 chip 删到只剩 1 层 | 该行回到 1 层形态（摘要消失），并**清除该行的展开标记**（1 层没有可展开内容，留着标记会让下次加到 2 层时莫名已展开） |

> **与现状的偏差**：`_poolOpen` 目前是窗口实例上的 `HashSet`，切配置 / 切图纸都不清空（§0.2-11）。规范要求在这两个时点显式清空——定级 P2-9，实现侧见 B.2-10。

#### 4.4.4 键盘与鼠标（**chips 永不逐个进 Tab 序列**）

| 焦点位置 | 按键 | 行为 |
|---|---|---|
| 摘要行 | `Tab` | 该行**只占 1 个停靠点**（0 层 / 1 层时是那个文字按钮，≥2 层时是摘要行） |
| 摘要行 | `Enter` / `Space` | 展开 / 收起；**展开后焦点落"当前层 chip"**（无则第一个 chip） |
| 摘要行 | `→` | 未展开：展开并进 chips；已展开：焦点进 chips（落当前层 chip） |
| 摘要行 | `←` | 已展开时收起并把焦点留在摘要行；未展开时无动作 |
| chips | `←` / `→` | 组内移动（roving focus），到行尾自动接下一行首位；**不循环**（到头停住） |
| chips | `Home` / `End` | 首个 / 末个 chip |
| chips | `Enter` / `Space` | 把该 chip 设为"下一条命令用的层"（= 点一下），焦点留在该 chip |
| chips | `Delete` | 删除该 chip（走 §6.5 撤销闭环）；`Backspace` **无动作**（避免与"搜索框删字"的习惯打架） |
| chips | `Ctrl+←` / `Ctrl+→` | 调整该 chip 顺序（= 拖拽，圆盘扇区序随动）；到首/末停住 |
| chips | `↑` / `↓` | 离开 chips，跳到上一行 / 下一行的摘要行（不在 chips 内绕行） |
| chips | `Esc` | 收起该行，焦点回摘要行 |
| chips | `Tab` / `Shift+Tab` | 离开本行，进下一个 / 上一个停靠点（**chips 本身不计入 Tab 序列**） |

> **硬约束（本条是本节的存在理由）**：一个配了 6 个图层的行，从"上一个停靠点"到"下一个停靠点"，**只需按 1 次 Tab**。若实现成 chips 逐个停靠，这一行要按 7 次——用户抱怨的正是这个。chips 内的移动只走 `←/→`。

**鼠标**

| 手势 | 行为 | 理由 |
|---|---|---|
| 点摘要行任意位置 | 展开 / 收起 | 整条可点，不给"只有箭头可点"的小目标 |
| 点 chip | 设为"下一条命令用的层" | 高频微操 |
| 按住 chip 拖动 | 排序（圆盘扇区序随动）；**位移 < 5 DIP 视为点击** | 手抖一两像素不该被当成拖动，否则换层极难点中 |
| 点 chip 内色块 **或色号文字** | 改这一层的颜色（只改这一层） | 色块 9×9 太小，色号一起做可点区 |
| 点 chip 内 `×` | 删除这一条映射（不触发父级的"设当前层"，必须吞掉事件） | 误触来源，事件处理上要 `Handled` |
| 点 `＋` | 开选择图层弹窗（追加） | — |

#### 4.4.5 16 层上限（圆盘扇区上限，不是性能限制）

| 场景 | 表现 | 文案 |
|---|---|---|
| 已达 16 层 | 摘要行尾的 `＋` **禁用**（`IsEnabled=false`，**不是隐藏、不是 hover 才出现**） | tooltip `一类最多 16 个图层（圆盘扇区上限）` |
| 已满时开弹窗 | 弹窗内勾选上限 = 剩余额度；超选时确定按钮禁用 | 弹窗内联 `最多再选 3 个（这一类已有 13 层，上限 16）` |
| 其他写入路径超限（手改配置文件 / 旧配置迁移） | **只保留前 16 个**，并把事实说出来 | 主面板提示行 `「线段」的图层池超过 16 个，只保留前 16 个` |
| 禁止 | ❌ 静默截断 ❌ 把 `＋` 直接消失（消失 = 用户以为不能加，实际是不能再加） | — |

#### 4.4.7 chip 的排版纪律（替代已作废的"折叠 `+N`"）

| 项 | 规定 |
|---|---|
| 排布 | `WrapPanel` **换行**，chip 间距 5，行间距 6；不折叠、不横向滚动 |
| 行数 | 不设上限；行高随内容增高（§4.4.2） |
| chip 内容 | `色块 9×9` + 层名（11 DIP，**不截断**，超长时该 chip 独占一整行并允许整体省略 + tooltip 全名）+ `色号 9.5` + `×` |
| 当前层 chip | `AccentSoft` 底 + `LineControl` 内描边 + 名称 `#FFFFFF`；**这是"下一条命令去哪层"的唯一行内依据**，不得只用底色区分 |
| 顺序 | chip 顺序 = 圆盘扇区顺序；拖拽 / `Ctrl+←→` 可改；改完立即标脏 |
| 禁止 | ❌ 折叠成 `+N`（**仅限本行**；CC 分类条的 `+N` 是另一回事，见 §3.5.3）❌ 逐行横向滚动 ❌ chip 内文字截断（`E-04 立面造…` 配不出层）❌ 把 chip 做进下拉/浮层 |

**删除图层 chip 的唯一入口与撤销（撤销闭环不变，入口随模型更新）**

| 项 | 规定 |
|---|---|
| 唯一入口 | **展开后 chip 右侧 `×`**（未展开时先点摘要行展开）。浮层、右键菜单、折叠容器里**都不提供**删除 |
| 撤销 | 删除后该行就地出现 `已删除「E-04 造型线」· 撤销`（**可视条 5 秒**），点它恢复；**同一时间只有一条**（再删一条就顶替上一条） |
| 键盘撤销 | 行内有焦点时 `Ctrl+Z` 撤销最近一次映射变更（删除/新增/修改），**多级回退，且不受 5 秒限制**——只要面板没保存、没关，就能一直退回到删除前（口径见 §6.5.1） |
| 删除最后一个 chip | 该行回到 **0 层形态**（只有 `＋ 选图层`）+ 状态 `待配置`；**不删整行**（类别是骨架，不可删） |
| 删到剩 1 层 | 摘要行消失，回到 1 层形态（`＋ 再加一层`），并清除展开标记（§4.4.3） |
| 不做什么 | ❌ 不弹确认框（可撤销就不确认）❌ 不做右键菜单 ❌ 不把删除塞进任何折叠容器 |

## 5. 胶囊条与圆盘的交互收敛

### 5.1 分工声明（两句话，写进帮助文案）

> - **改"用哪套配置"→ 点胶囊条上的配置名。**
> - **改"下一条命令去哪一层"→ 右键长按弹圆盘。**

两者都影响"接下来画到哪"，但改的是不同层的东西：配置是"整张规则的集合"，圆盘是"当前这一类的具体一层"。规范上必须**禁止**出现第三种入口（例如在某处再放一个"换层"下拉），否则三处互打。

| 能力 | 胶囊条 | 圆盘 | 说明 |
|---|---|---|---|
| 显示启用态 | ✅（唯一权威） | ❌ | 圆盘不弹时用户只能看胶囊条 |
| 显示配置名 | ✅ | ❌ | 圆盘中心显示"类别 · 当前层"，不显示配置名（中心太小） |
| 显示当前层 | ✅ | ✅（中心一行） | 允许冗余，两处必须同源 |
| 切换配置 | ✅（配置清单） | ❌ | 圆盘不做配置，避免长按后出现二级菜单 |
| 切换当前层 | ❌ | ✅ | 胶囊条不做换层：它是常驻浮窗，可点区域越少越好 |
| 打开主面板 | ⚠️ 仅"配置清单"底部「管理配置…」 | ❌ | 不给胶囊条主体加点击面：它盖在绘图区上，抢点击是硬伤 |
| 临时禁用 | ❌ | ❌ | 用 `ALOFF` / 主面板开关；胶囊条只显示结果 |

### 5.2 重复入口的处置

| 重叠点 | 处置 | 理由 |
|---|---|---|
| 胶囊条 vs 主面板都能"看到配置" | 胶囊条只读 + 可切；主面板可改 | 读与写分离 |
| 圆盘 vs CC 都能"换层" | 圆盘 = 换**当前层**（不搬图元）；CC = 搬**图元**去某层（或切当前层） | 语义不同，但要在文案上区分：圆盘命令行写"下一条命令生效"，CC 写"N 个图元 → 层" |
| 主面板 [图层切换] 图标 vs CC 命令 | 同一件事，保留图标（发现性） | 图标 tooltip 已写"命令 CC"，保留 |
| CC 标题栏 `⚙` vs 主面板 | **保留，但换图标（窗口+箭头）+ 12 净空 + tooltip「打开主面板（QH）」** | 它是 CC → 主面板的唯一捷径；误点由净空解决，不由删按钮解决（§10.2、视觉 §5.1-3） |

### 5.3 圆盘的高风险点与降级

| 风险 | 现状 | 规范 |
|---|---|---|
| **静默不弹** | 未启用 / 配置空 / 该类别 <2 层 / 构建失败 → 直接 return false，无任何提示 | **必须给反馈**：胶囊条闪 `圆盘：这一类只配了 1 个图层` / `圆盘：插件未启用` / `圆盘弹出失败，ALTRACE 看原因`。静默是最伤的失败形态（用户会反复长按） |
| 扇区 > 16 | 只取前 16 | 中心提示行加 `前 16 层` 角标；命令行提示"完整列表用 CC" |
| 中心语义 | hub 显示类别 + 当前层（可两行/一行） | 保持只读，**中心不可点**（点中心 = 取消）。中心必须能一行说清"这是哪一类"，否则扇区没有意义锚点 |
| 与 CAD 右键菜单冲突 | 长按才弹，短按照旧 | 保留；设置里已有"长按时长"。规范要求：长按阈值改动后，主面板提示行同步文案 |
| 切层时正在画命令 | `SwitchToLayer` 只影响下一条命令 | 命令行必须写 `（下一条命令生效）`——现状已有，保留为硬要求 |
| Esc / 空白取消 | 闪"已取消" | 保留；"已取消"三个字比"什么都没发生"更可信 |

### 5.4 胶囊条文案与状态

| 状态 | 显示内容 | 备注 |
|---|---|---|
| 已启用 + 已配 | `● 配置名 │ 当前层名` | 层名过长时**中间省略**（保前缀与后缀），tooltip 全名 |
| 已启用 + 配置全空 | `● 配置名 │ 未配置图层`（层段变灰） | 引导用户去主面板 |
| 已停用 | `● 已关闭`（配置 chip 显示"已关闭"、层段隐藏） | 现状已如此，保留：显示一个不生效的层名是误导 |
| 瞬时反馈 | 切层/圆盘/切换后 1.4s 用目标层名覆盖层段 + 边框亮起 | 现状已实现 |
| 超宽 | 最宽 320 DIP，配置名 ≤14 字符截断、层名 ≤24 字符截断 | 4K 200% 下同样按 DIP |

## 6. 反馈与容错规范

### 6.1 三个通道，各有各的活

| 通道 | 用途 | 时长 | 禁止 |
|---|---|---|---|
| **CAD 命令行** | 可追溯的结果与原因；带 `[图层切换]` / `[Y_图层工具箱]` 前缀；写清"撤销方式" | 常驻（滚动） | 不用命令行当唯一反馈（用户不看命令行） |
| **胶囊条 Flash** | 即时、短暂、无需记忆的结果（"切到哪了"） | 1.4s | 不放长句、不放过长图层名（会被截断成无信息） |
| **界面内联（banner / 模式条 / 提示行）** | 需要用户当场决定的错误与警告；与操作上下文相关 | 常驻到状态改变 | 不用 MessageBox 打断高频流 |
| **确认框** | **仅**不可撤销且会丢数据的动作（见 §6.3） | — | 高频动作里一律不用 |

**同一事件最多两个通道**：一个"当下看见"（胶囊条或内联），一个"事后可查"（命令行）。三个通道重复说同一件事 = 噪音。

### 6.2 文案模板表

> 全文口径：自 v1.2 起统一用「**未存盘**」。本表**只含新文案**；文中其他位置出现的「未保存」全部是旧文案引用（§0.2 现状核对、§4.2 用词修正对照、§7 P0-5/P1-2 的现象描述），**不得据其回改开发**。
>
> **A/B 变体（主面板脏态提示行）由「发布范围」决定，不由文案偏好决定**——发布版含「还原到打开时」就只能是 A，不含就只能是 B。**禁止**因"读着更顺""更像不打扰用户"之类的审美理由挑选变体；选错变体的后果是给用户指一个不存在（或实际存在）的动作，属于缺陷而非风格。改定变体的唯一依据是发布范围，且与发布说明顶部告知、界面无残留暗示三者同批（§4.3）。

### 6.3 二次确认的判定阈值（什么必须问，什么别烦人）

**必须确认（不可撤销 + 丢数据）**

| 动作 | 为什么 | 形态 |
|---|---|---|
| 删除配置 | 一整套映射消失，无撤销 | 确认框，正文写清"12 项映射会一起删除，无法撤销" |
| 保存失败后仍关闭 | 改动会丢 | 确认框，主按钮是"仍然关闭"，默认不关 |
| 放弃未存盘映射（若将来提供"还原/关闭不存"） | 批量改动丢失 | 确认框，默认"返回保存" |

**不要确认（可撤销 / 可重做 / 高频）**

| 动作 | 替代方案 |
|---|---|
| CC 应用 N 个图元到某层 | 直接做 + 命令行给 `可用 U 撤销` |
| 圆盘切层 | 直接做（本来就不影响已画图元） |
| 切换配置 | 直接做（随时可切回） |
| 目标层已关闭 | 内联提示 + 自动打开 + 结果里说明（不要中途 MessageBox，现状 P1） |
| 删除单个图层 chip | 直接做（可重新添加） |
| 拖拽排序配置 | 直接做 |
| 关闭图层切换面板 | 直接关（面板内只有预览，无落地改动） |

**判定公式**：`不可撤销 && 会产生数据丢失 && 非高频` → 才确认。三者缺一，用"可撤销 + 事后提示"替代。

| 失败 | 降级方案 |
|---|---|
| 配置文件写不进去 | 不关窗；底部横幅给路径与原因；主线功能（归层）仍按内存配置工作 → **功能不残** |
| CC 因 CAD 上下文取不到选择集 | 提示 `请先选好图元再执行 CC，或直接回车只切当前层`；不崩溃 |

| 删除后发现删错 | **已闭环，不在本节降级**：行内 5 秒撤销条 + `Ctrl+Z` 多级回退（直到保存/关窗）。口径见 §4.4 与 §6.5.1，问题定级 P1-11 |

### 6.5 撤销口径

- **能撤销的**（图元移动、当前层切换、**删除图层 chip**）→ 命令行统一后缀 `（可用 U 撤销）`；chip 删除走**行内 5 秒「已删除 · 撤销」+ `Ctrl+Z`**（见 §4.4），不要弹 toast 教用户按 Ctrl+Z。
- **不能撤销的**（删配置、改名导致引用失效）→ 在**做之前**说清（确认框正文），不要做之后再说"无法撤销"。
- 撤销提示**只在命令行出现一次**，不重复、不闪烁。

#### 6.5.1 「撤销条 5 秒」≠「撤销能力 5 秒」（口径写死，不得混用）

这两件事必须分开定义，混用会产生一个比"没有撤销"更糟的状态：**能退，但界面暗示不能退。**

| 口径 | 定值 | 说明 |
|---|---|---|
| **可视撤销条** | **5 秒**（从出现即计时；**同一时间只保留一条**，再删一条就顶替上一条） | 这是"降低打扰"，不是"撤销窗口关闭" |
| **撤销能力** | **直到保存 / 关窗** | `Ctrl+Z` 可**多级**回退，**不因撤销条消失而失效** |

**由此推出的三条硬约束**：

1. **撤销条消失后，`Ctrl+Z` 必须照旧可用**。任何实现只要让"条没了 = 退不回去"，就是缺陷（P1-11）。
2. **撤销条消失后不追问、不补提示**——不允许为此再弹一次 toast 或补一行"仍可按 Ctrl+Z"。用户已被告知过一次（§4.4 行内条），重复提示比沉默更吵。
3. **保存/关窗之后能力自然终止**：保存 = 已落盘，关窗 = 本次会话结束。此时 `Ctrl+Z` 无动作，且**不需要**任何"已来不及撤销"的提示——用户按保存时已经明确知道这是在写盘（§4.3 未存盘三处口径）。

**`Ctrl+Z` 的作用域（别做复杂）**：

- **只回退本面板本次会话内的映射变更**（增、删、改），多级栈，每条一次。
- **不碰 CAD 自己的 undo 栈**。跨系统 undo 是另一个工程（两套栈的合并语义、U 命令交错、事务边界都不同），**V1.0 不做，也不要顺手做**——做半套会让用户按 `U` 撤图元时连带撤掉映射，或反之，比没有更坏。
- 面板外（图纸里的图元）的 `Ctrl+Z` 行为完全不变，仍由 CAD 负责。

## 10. 防呆设计 与 漏画状态盘点（v2.4 · 2026-11-10）

> **触发（用户原话）**：「然后你再去思考下有没有漏设计的地方，防呆设计；然后你要明白要锦上添花而不是乱改我原来的功能……如果原来的功能优于你删除的功能那就得不偿失了。要从整体插件的设计理念出发，以用户思维设计」。
>
> **本章的边界（最重要的一条）**：**只补画、不新增**。下面每一条都能在现有源码或前几章规范里找到出处；本章不新增确认框、不新增开关、不新增流程、不替换任何控件，只把"代码里已经存在、但静态稿从来没画过"的失败分支画出来。**防呆 ≠ 多加弹窗**。

### 10.1 先讲清这套插件的设计理念（从源码读出来的，不是编的）

| 理念 | 源码 / 现象依据 | 对用户意味着什么 |
|---|---|---|
| **余光可见** | 胶囊条常驻只读、标题栏 3px 状态条、状态列 4 态 | 状态不需要"点开看"，扫一眼就知道开没开、存没存 |
| **手不离光标** | 右键长按 0.18s 弹圆盘；不做二级菜单 | 高频换层不能有窗口往返 |
| **一次配好，长期复用** | 配置 = 一套「类别 → 图层池」映射；跨图纸跨会话 | 改配置是低频重活，允许慢；改当前层是高频轻活，必须快 |
| **不打断命令流** | `Hook` 命令前后自动切层 / 还原；高频路径零确认 | 归层这件事不该让 CAD 命令停在中途 |
| **失败必须出声** | `Config.Save()` 注释「静默失败会让用户以为保存了」；`OnClosing` 注释「存不进去就不能装作存好了」；`PieHost` 失败分支要 Flash | **静默 = 缺陷**。这是本章所有防呆条目的母原则 |

由此推出四条防呆原则（后续任何一轮都按这四条判）：

1. **不可逆要有名字和数量**：删配置要说配置名 + 「N 项映射一起删，无法撤销」；关窗丢改动要说「这次的改动会丢失」。
2. **静默要有话说**：圆盘不弹、写盘失败、目标层已关闭，都必须有一句人话 + 一个能查的出路。
3. **入口要常驻**：加层 `＋`、配置四图标、摘要展开箭头，都不许靠 hover 或菜单才出现（§4.1 / §4.1.1 / §4.4）。
4. **补偿要近、要快**：删掉最后一个 chip 给 5 秒就地撤销 + `Ctrl+Z` 多级回退；不把撤销藏进"更多"。

### A.2 焦点与键盘

1. **焦点永远可见**：1 DIP 实环 `#60A5FA` + 1 DIP 外扩 `#4060A5FA`（由容器 1 DIP padding 承载，合计视觉 2 DIP）。不得用"仅颜色变化"代替。单环方案在 `UseLayoutRounding` 下有一半概率被舍进相邻像素——这是"有时候看不见"的根因，必须用环形 + padding 的双层结构。
2. **焦点顺序 = 视觉顺序**：搜索 → **chip 组（1 个停靠点）** → **模式条「改选 ▸」** → **最近快捷行（1 个停靠点）** → 列表 → 勾选框 → 取消 → 主按钮。
3. **组内只占 1 个停靠点（roving focus）**：chip 组与快捷行各自只有一个 Tab 停靠点，组内用 `←/→` 移动，`Tab` 直接跳到下一个区域。理由：逐个停靠会让"到列表"要按 5~6 次 Tab，对常年键盘的绘图员反而更慢；但**组内必须始终有一个可见焦点**（不是整组高亮），否则用户不知道自己停在哪。
4. **读数面板不进 Tab**：模式条本体不可点、不可聚焦，只有右侧「改选 ▸」是控件（§3.4）。
5. **无鼠标独占操作**：双击 = Enter；拖拽排序 = `Ctrl+←/→` 移动 chip（chips 是横排，方向键跟着排布走）；拖窗口不算功能。
6. **陷阱禁止**：Tab 序列里不允许"可聚焦但无动作"的元素（旧的"最近使用 / 全部图层"标题行就是这种，已随分组标题形态一并删除）。
7. **Esc 不吞输入**：文本框内 Esc 先放弃输入，第二次才关窗。
8. **对话框**：确认框默认焦点在"安全"选项（取消/否）；`Enter` 不默认触发危险动作。
9. **`Ctrl+Z` 与撤销条脱钩**：面板内有焦点时 `Ctrl+Z` 生效，作用域 = 本面板本次会话内的映射变更（增/删/改），多级回退，**直到保存/关窗才终止**；**撤销条 5 秒消失不影响它**（§6.5.1）。撤销条消失后**不得补任何"仍可按 Ctrl+Z"的提示**——重复告知比沉默更吵。
10. **不接管 CAD 的 undo 栈**：面板内 `Ctrl+Z` 不撤销图元，图纸里 `U` 也不撤销映射。两套栈各管各的，不做合并（合并属独立工程，半套实现会互相误伤）。
11. **主面板映射行：一行 = 一个 Tab 停靠点**（v2.2）。收起态是摘要行（0/1 层时是那个 `＋` 文字按钮）；展开后 **chips 不进 Tab 序列**，组内用 `←/→` 移动，`↑/↓` 直接跨到相邻行。判据：**一个 6 层的行最多按 1 次 Tab 越过**（§4.4.4、验收 32）。

### A.3 读屏与语义

- 图标按钮必须有名称：`新建配置` / `重命名配置` / `复制配置` / `删除配置` / `打开主面板` / `图层切换` / `关闭`（**不存在"更多配置操作"**——`⋯` 菜单已作废，见 §9）。
- 列表需报读"图层名 + 颜色 + 状态"（例：`E-04 造型线，白色，正常`）；**列表里已没有分组标题**，只有数据行与空状态（视觉侧红线 15）。
- **CC 前缀组 chip** 报读：`前缀组 A，6 个图层`；当前筛中的那个追加 `，已选中`。不用"分类"这个词（§0.1）。
- **主面板图层池摘要行**用展开/收起语义（`ExpandCollapsePattern` 等价），报读：`线段，6 个图层，当前 E-04 造型线，已展开 / 已收起`；展开后 chips 报读 `E-04 造型线，白色，当前层` + `，共 6 项`。
- 「最近使用」快捷行是独立的 button group，组名 `最近使用`，组内成员报读 `E-04 造型线（最近使用）`，不得被读成列表的一部分。
- 模式条、计数、错误用 `LiveRegion` 语义（界面即时报读，不依赖用户主动找）；模式切换（对象↔当前层）必须报读。
- 圆盘是纯自绘，键盘不可达属可接受（有 CC 与命令行等价路径），但**必须在帮助里说明**圆盘的键盘替代是 CC。

### B.2 给前端实现（交互契约，不含代码）

1. **"当前项"唯一**：键盘游标、鼠标选中、Enter 应用、图纸预览共用一个状态；不得存在第二套。
2. **模式判定一次**：打开面板时判定对象模式/当前层模式，之后只允许通过「改选」切换，不随图元反复抖动（图元全失效时降级一次并提示）。
3. **不新增窗口**：任何新需求优先用内联提示或轻量弹层，禁止再加 MessageBox（保存失败确认与删除配置除外）。
4. **写入时机**：状态类（启用、当前配置）即时落盘；结构类（映射、快捷键）延后到保存。
5. **失败不关窗**：应用失败、保存失败一律保留窗口与上下文。
6. **所有文案集中在文案表**（§6.2），不得在代码里散写字符串。
7. **一次性提示**：主面板"首次关窗告知即时生效"、引导条"这个配置还没设过图层"，各自只出现一次并持久化标记。
8. **单一口径**：跨角色的结论（涉及视觉 / 前端 / 交互任两方）**由 team-lead 统一对外发布**，各角色不在对方文档里单方落结论。本文档是交互侧唯一口径，若发现与他方文档冲突，先报 team-lead，不在两处各写一版。
9. **撤销栈边界（新）**：面板内维护一个**只装映射变更（增/删/改）**的多级栈，随面板会话存活，保存或关窗即清空；`Ctrl+Z` 只消费这个栈。**不得**把映射变更塞进 CAD 的事务/undo 记录，也**不得**监听 CAD 的 `U` 去反推撤销——两套栈刻意保持互不感知。清单里删到空不是"整行删除"，所以撤销恢复的粒度是**单条 chip**，不含"行结构"。
10. **展开态是纯内存状态（v2.2）**：主面板的"哪些行展开了"用一个**随窗口存活的内存集合**保存，**不写 ini、不进配置、不跨会话**；在**切配置 / 切图纸 / 关窗**三个时点**显式清空**（现在的实现只在窗口构造时初始化，切配置不清，属 P2-9）。**不要**为了"记住展开态"去改配置文件格式。
11. **两套分类不可共享实现（v2.2）**：主面板的 **8 个固定类别**（语义、配置的一部分）与 CC 的**前缀组**（从图纸图层名实时算出、不落盘）是两件事，**不得**共用同一个枚举/常量表，也不得把前缀组写进配置。前缀算法只有一份实现（`LayerCategoryService`），CC 是唯一消费方。
